# النشر العام والمخاطر

## هل نشر المشروع يعطي شخصًا وصولًا إلى Yasmina أو البيت؟

**لا، طالما تُنشر النسخة المنظفة فقط.**

الـrepository العام لا يحتوي على:

- Home Assistant token.
- Yango/Yandex cookies أو session tokens.
- OAuth client secret أو link code الحقيقي.
- Skill ID الحقيقي.
- Yasmina device/account ID أو serial.
- IP/MAC الحقيقي للتلفزيون أو السماعة.
- ADB private key.
- قواعد بيانات OAuth/runtime.
- Scenario IDs الخاصة بالبيت.
- تسجيلات صوتية.
- Domain الإنتاج الحقيقي.

بدون هذه الأسرار لا يمكن لشخص استخدام الكود للوصول إلى تجهيز البيت الحالي.

## هل يمكن أن يؤثر النشر على Yasmina الموجودة عندنا؟

نشر source code المنظف **لا يغير أي إعداد على السماعة** ولا يرسل لها أي أمر.

الخطر يبدأ فقط إذا تم نشر credential أو identifier خاص عن طريق الخطأ، أو إذا تم تعديل الخدمة الحية لتستخدم إعدادات public/example. لذلك:

- الإنتاج يبقى منفصلًا عن repository العام.
- لا نعمل auto-deploy من GitHub إلى البيت في v1.0.
- أي تحديث مستقبلي يمر باختبارات ثم نشر يدوي متحكم فيه.

## هل Yango ممكن يقفل القنوات؟

لا توجد ضمانة أن أي API يبقى ثابتًا للأبد.

نقسم المسارات إلى نوعين:

### 1. المسار الذي ننشره

Smart Home provider + account linking + Home Assistant.

هذا هو المسار المقصود للاستخدام كتكامل منزل ذكي. Yasmina رسميًا تدعم التحكم في smart-home devices وربط حسابات مزودي الأجهزة.

حتى هذا المسار يمكن أن تتغير مواصفاته أو سياسات النشر مستقبلًا، لذلك الكود versioned والاختبارات منفصلة.

### 2. مسارات البحث غير الموثقة

أثناء البحث تم فحص واجهات محلية/داخلية لمعرفة حدود Yasmina وإمكانية التقاط الكلام الحر. هذه المسارات **ليست مطلوبة** للتحكم الحالي في النور أو التلفزيون.

تفاصيلها التنفيذية لا تدخل الإصدار العام v1.0 للأسباب التالية:

- قد تتغير مع Firmware بدون إشعار.
- ليست جزءًا مطلوبًا من المنتج النهائي.
- نشر تفاصيل داخلية غير لازمة يزيد سطح الصيانة والمخاطر.
- لا نريد ربط استقرار مشروع المنزل بمسار غير رسمي.

لو احتجناها مستقبلًا تُحفظ كـprivate research notes منفصلة عن public release.

## سياسة الأمان قبل كل Release

قبل أي نشر عام:

1. شغّل unit tests.
2. شغّل compatibility tests.
3. افحص Private IPs وUUIDs وtokens وpaths وdomains.
4. راجع diff يدويًا.
5. لا ترفع runtime/ أو secrets/ أو ADB keys.
6. لا تنقل ملفات من production مباشرة إلى Git بدون sanitization.
